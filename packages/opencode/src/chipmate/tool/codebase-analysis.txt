Analyze C/C++ code relationships and behavior, returning grounded evidence with file paths and line ranges.

## When to use

- Use this tool when precomputed C/C++ graph relationships would materially supplement direct source inspection
- Treat this tool as optional supporting evidence, not as a prerequisite for C/C++ questions
- Callers, callees, call chains, definitions, declarations, references, ownership, and cross-module flow
- Macro, register, MMIO, bitfield, and hardware-interface usage analysis
- State machine, transition, lifecycle, and module-flow questions
- Error path, cleanup path, resource lifetime, and impact analysis
- Questions that need graph-derived relationship evidence with local file paths and line ranges

## When to use Grep instead

- The question only asks where an exact identifier, literal, macro, or text pattern appears
- No caller/callee relationship, control flow, state transition, lifecycle, error path, cleanup path, or impact analysis is requested
- Directly locating and reading a small number of known files is sufficient to answer the question
- Use `Read` after locating a known file or line to verify the source text

## When to use semantic_search instead

- Conceptual natural-language search without an exact identifier where C/C++ relationships are not needed
- Finding broadly related snippets by meaning before using `Grep` or `Read`

## Constraints

- Use `path` only for subdirectories inside the current workspace.
- Treat answers as ungrounded unless the returned evidence includes file paths and line ranges.
- If the index is not ready or returns no source-backed evidence, fall back to `Grep` and `Read` for this request instead of retrying this tool repeatedly.
- In Phase 5, hybrid mode can return C/C++ graph evidence, lexical BM25 evidence, and existing ChipMate vector evidence; rerank, state-machine extraction, and module summaries are not enabled here.
