# ChipMate 发行说明

## 1.0.19

相较 1.0.18：

- 统一缩短 Code RAG 与 Document RAG 的 LanceDB 工作区和安全代际目录，在 Code Insiders 等深层 `globalStorage` 路径中为事务临时文件预留空间，避免写入时因 Windows 路径过长触发 `os error 3`。
- 安全复用仍在路径预算内的旧索引；旧目录过长时自动在紧凑路径完整重建，并只在新索引完成和校验后清理旧目录。显式配置的根目录仍过长时会在写入前给出实际长度和短目录建议。

## 1.0.18

相较 1.0.17：

- 新增源码依据驱动的详细设计生成流程：按模块收集证据、异步生成并校验结构化设计内容，支持输出包含架构图与源码依据的 Word 文档。
- 新增文档专用只读 Agent：默认仅检索文档，只有用户明确开启后才允许只读检索代码，并在范围切换时保持工具权限隔离。
- 支持对编辑器选区内最多十个 C/C++ 函数批量生成高可信中文注释，统一进入原生 Diff，由用户决定是否应用。
- 新增通用 Excel 导出工具：具备标准工具调用能力的模型可按结构化表头和数据生成排版工整的 `.xlsx` 工作簿，并在交付前完成行列、内容、格式和文件完整性校验。

## 1.0.17

相较 1.0.16：

- 将 Windows LanceDB 运行库裁剪为本地文件系统专用构建，在保留低端 x64 CPU 兼容性的同时把 VSIX 控制在旧版自动更新上限以内。
- 将新版客户端的 VSIX 下载安全上限提高到 512 MiB，并继续阻止未来 Windows 发布包突破旧客户端可下载边界。

## 1.0.16

相较 1.0.15：

- 修复 Windows 文档 RAG 的默认目录比代码 RAG 更长、导致新建 LanceDB 候选仍可能在事务落盘时触发 `os error 3` 的问题；新 generation 使用更短的安全标识，并按真实目录校验路径预算。
- 修复 Windows 升级后继续复用旧版超长 active LanceDB generation、导致首次事务写入以 `os error 3` 失败的问题；旧索引现在只作为回退保留，新版会在紧凑路径完成全量候选重建、回读验证和原子切换。
- 修复 Windows 升级或重载期间旧索引进程未完整关闭、可能删除新进程正在接管的 LanceDB 候选 generation 的问题；正常关闭现在会完整等待原生 writer，并保留可恢复候选索引。
- 升级并精简 LanceDB Windows x64 原生运行库，修复缺少 AVX、AVX2、FMA 或 F16C 的虚拟机在余弦向量查询时可能以非法指令退出的问题，同时确保 VSIX 保持在旧客户端可下载的 256 MiB 上限以内。
- 压缩新建 LanceDB 索引的落盘路径，并安全重建旧版未完成候选索引，降低 Windows 长路径导致建库失败的风险。
- 将新版客户端的 VSIX 下载安全上限提高到 512 MiB，并在构建阶段继续阻止 Windows 发布包突破旧客户端的下载上限。

## 1.0.15

相较 1.0.14：

- 修复大型工作区在内存受限时反复从零建立向量索引以及 LanceDB 合并写入超时的问题；索引进程现在串行执行原生写入、自动拆分超时批次，并通过 checkpoint rollover 继续未完成的安全代际，再以较低并发完成候选索引读回验证。
- 修复 worker 换代后 Document RAG 首次构建与强制重建的分块数不一致，并为候选索引增加原子提交、恢复与源向量读回验证。
- 支持没有代码文件的纯文档工作区安全完成空 Code RAG，不再阻塞 Document RAG 建库。
- 修复直接调用 Document Search 时文档索引仍在异步初始化、导致工具过早返回未就绪错误的问题。

## 1.0.14

相较 1.0.13：

- 修复大型 Windows 工作区中本地 LanceDB 合并写入因并发竞争和固定短超时而反复失败的问题；向量写入现在串行执行，拥有更充足的完成时间，并会在超时时自动拆分批次重试。

## 1.0.13

相较 1.0.12：

- 新增 C/C++ 高置信度函数注释：围绕光标所在函数重复理解、核验源码证据，并通过原生 Diff 确认后写入简体中文注释。
- 改进文档 RAG 对异常超长单行和嵌入服务输入上限的处理；在服务拒绝过长输入或批次时自动缩小失败范围重试，同时保留正常文档的分块质量。
- Markdown 文件现在只由文档 RAG 建立索引，避免代码 RAG 重复处理并返回 `.md`、`.markdown` 文档。
- 修复代码 RAG 将正常重复代码块的相同 embedding 误判为服务响应塌缩、导致部分批次反复失败和索引进度停滞的问题；继续拦截多个不同文本或运行时哨兵确认的真实向量塌缩，并减少低配置机器上的无效向量对计算。
- 修复扩展自动补全使用的 Tree-sitter 运行时与 WASM 版本或路径不一致时解析不可用的问题，并将匹配的 WASM 作为离线运行时必需文件打入 VSIX。
- 修复斜杠命令筛选后键盘高亮项与回车实际选择项不一致的问题。
- 在已完成回复的操作行显示本轮完成耗时，并保留不同 Agent 的状态样式。
