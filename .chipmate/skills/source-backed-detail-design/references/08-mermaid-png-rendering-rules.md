# 08 Mermaid PNG Rendering Rules

> 完整 Word 任务的 Mermaid 与 PNG 生命周期由 `source_backed_design_job` 独占。本文件以下直接调用、claim 和 batch 规则仅供窄范围源码图兼容使用；不得在控制器任务中自行调用公共 Mermaid 工具或恢复旧批次协议。

`SBDD_RULESET_REVISION=2026-07-source-semantic-v122`. For source-backed renders, tool-returned `wordFitStatus` and `documentReady` are authoritative. A PNG with `wordFitStatus=split-required` or `documentReady=false` is evidence-only: it cannot count as a terminal base/focused figure or enter Word. New readable replacement claims use unique IDs plus `splitFromDiagramId` naming the oldest pending parent; their combined visible node/edge IDs must cover it before any other view. The next manifest must contain exactly the latest suggested child IDs and no unrelated item, so a repair cannot consume attempts by rerunning the original batch. Accept the replacement set only when the repair result lists that parent in `resolvedSplitDiagramIds`; use the readable child PNGs for Word. A split-required intermediate probe does not become another required parent. The tool's calibrated minimum scale is `0.65`, matching the arithmetic below.

源码详设调用不得填写 `remoteEndpoint`、猜测公网或内网 URL、安装渲染器，或要求用户配置渲染服务。工具会确定性选择已配置的服务，并在失败时尝试当前环境已有的本地 `mmdc`；一次瞬时基础设施失败只写入 checkpoint，下一次“继续”重试，不得借此缩减图形矩阵或提前创建 Word。

Each primary claim uses exactly one canonical `diagramType`: `architecture`, `business-flow`, `code-flow`, `state-machine`, or `data-lifecycle`.

For a full multi-unit figure turn, the immutable orchestration manifest and root-verified prose audits are prerequisites. Process only the current frozen 1–3-unit batch; do not discover, rename, add, or remove units. Author and reread every assigned MMD/claim pair, then use one source-backed batch manifest and one sequential batch render call before writing compact per-unit results. Do not create Word, merge, materialize TOC, or delegate during a figure turn. Ordinary Mermaid and narrow source-backed figure sessions do not enter this batch protocol.

Before the first claim write, apply this compact safe profile. Copy each DesignUnit ID exactly from the census. Claim every visible node and visible arrow exactly once. A conceptual module, business step, lifecycle phase, boundary, or aggregate edge omits source symbols and uses an evidenced `dependency`; use `direct-call`, `callback`, `ownership`, `data-flow`, or `state-transition` only when both exact endpoint symbols and the relation site are already proved. Keep `sourceHash` as literal `$MMD_SHA256`; the batch binds that sentinel in memory to the exact current MMD hash and leaves the sentinel reusable, so never calculate or edit it afterward. A prose unit that says no persistent state machine must have adjacent topic status `N/A`, an `N/A` coverage slot, and no state-machine MMD/claim. A real state diagram uses only proved `state-transition` edges or `unknown` edges visibly labelled `待确认`; event sequences, phases, handler lists, and dispatcher branches are not states. If the validator reports `semantic-state-transition-downgrade`, never bulk-change relations: either add exact guard/action proof without deleting semantics or return to the prose audit and record evidenced `N/A`.

## 1. ChipMate render route

Mermaid `.mmd` is the editable diagram source. High-DPI white-background PNG is the Word figure artifact. Do not bundle or install renderer dependencies during a task. Prefer the configured remote renderer; a pre-existing externally installed `mmdc` is acceptable only when the runtime already exposes it as an explicit fallback. Never use `bash`, a package manager, `npx`, `npm`, `bunx`, `pip`, a downloaded browser, or a custom script to create a new rendering path after `render_mermaid_diagram` fails. Preserve the tool failure and stop or use its built-in fallback only.

Revision override: ignore any older wording below that says the batch persists a concrete `sourceHash`. The current batch binds literal `$MMD_SHA256` only in memory and keeps the claim reusable after MMD edits.

checkpoint 并停止，禁止退回普通 Mermaid。`valid-with-unknowns` 的每条未知关系必须在对应节点或边上可见“待确认”。全新普通画图会话不得传 semantic 字段、batch manifest 或创建 claim。

批处理 hash/container 语义以本段为准：`$MMD_SHA256` 只在内存中绑定当前 MMD，不会被具体 hash 覆写；MMD 修改后保持该字面值即可。批处理从最终 MMD 确定性补齐遗漏的 node `container` 并持久化，显式填写的错误 container 仍会失败。独立单图不接受该占位符，必须使用准确 hash。

窄范围架构图不会加载范围 reference，因此必须直接使用下面的唯一 census 结构；不得改成 `targetModule`、`confirmedSubmodules`、`designUnitId` 列表或其他自定义字段，也不得附加第二套平行子模块清单。完整 C/C++ 模块的 `targetSourceRoot` 必须是精确目标源码目录，`implementationUnits` 必须逐个列出该目录下实际 `.c/.cc/.cpp/.cxx`。用户明确只要求一个实现文件的窄范围图时，claim 的 `scopePath` 与 census 的 `targetSourceRoot` 可以直接填写该 `.c/.cc/.cpp/.cxx` 文件，且 `implementationUnits` 必须把同一文件恰好列出一次；校验器使用其父目录作为 CodeGraph 查询前缀。不得借单文件模式逃避完整模块任务的实现文件覆盖：

## 2. Artifact indexing

The render tool writes `.mmd` and `.png` artifacts under the active product profile's artifact location. Do not assume the concrete directory; use the path returned by the tool. When the work package requires `04-diagrams/mmd/...` and `04-diagrams/png/...`, create or update `04-diagrams/diagram-index.md` and the coverage CSVs to map the requested logical diagram path to the tool-returned artifact path.

## 3. Diagram syntax and first-pass visual safety

Business flow and base architecture diagrams default to `flowchart TD`; a base architecture target container uses `direction TB`; state overview diagrams use `stateDiagram-v2` when appropriate. Node ids must use ASCII letters, digits, and underscores. Required base diagrams use the renderer's plain white default theme and must not contain init/theme directives, `classDef`, `class`, `style`, or `linkStyle`; this removes parser/version drift and prevents a saturated target container from becoming the whole page background. Optional focused diagrams also prefer the default theme and may use custom styling only when the current Render Service has already proved the exact syntax compatible. User-visible diagram titles, role labels, annotations, branch results, and generic responsibilities default to Simplified Chinese; when a source symbol is relevant, preserve its exact spelling on a separate line. Never shorten, translate, normalize, or invent a source identifier or alias. Generic English role words such as `Core`, `Entry`, `Egress`, `Backend`, `Persist`, or `Crypto` cannot replace a Chinese explanation or an evidenced component/interface name. Edge labels must be readable business conditions and should quote punctuation-heavy labels. Exact C conditions belong in evidence tables, not overloaded node labels.

For a base view, detailed does not mean verbose labels. Every node carries only an exact evidenced name, one concise Chinese responsibility phrase, and at most one exact source anchor. A node must not contain a function/field/state inventory, structure layout, capacity, threshold, signature, parameter list, diagnostic counter list, or prose paragraph. Show detail through the complete applicable node set and source-backed dependency, branch, transition, handoff, error/recovery, and lifecycle edges. Put implementation inventories in focused diagrams, figure captions, evidence tables, or prose. Before validation, reject a base source that contains any forbidden styling token or an inventory-shaped node.

File-name-only, symbol-only, or final-response counts are invalid ledger evidence.

## 4. Word insertion

Before Word creation, maintain separate `CoverageSlot` and `DiagramRequirement` ledgers. `CoverageSlot` has exactly `5D` base rows for the one target module and every target-owned confirmed submodule, where `D = 1 + confirmedSubmoduleCount`; evidenced owning modules are excluded. `DiagramRequirement` has one row per actual base or focused figure and records `diagramId -> baseOrFocused -> owningSlot -> complexityInstanceIds -> sourceEvidence -> mmdPath -> sourceStatus -> syntaxValidation -> semanticCoverage -> pngPath -> visibleFigureId -> targetSection -> renderDisposition -> visualQaStatus -> wordInsertionStatus`. Business-diagram `semanticCoverage` lists Flow family IDs, business edge IDs, async handoff IDs, and terminal step IDs from the closed census; syntactically valid but semantically incomplete figures remain `MISSING`. Process the current frozen 1–3-unit batch and checkpoint both ledgers before the next. Every non-`N/A` base slot needs a unique primary PNG; one PNG cannot satisfy another design unit or view type. Require `uniqueSuccessfulDiagramIdCount = successfulRenderedItemCount = requiredFigureCount`, every successful batch result item to map to exactly one required Diagram ID, and exactly one current terminal PNG per Diagram ID; batch-call count is never compared with image count and retries remain diagnostics. Also require `unassignedSlotIdCount = pendingRenderSlotCount = missingRenderedPngCount = remainingRequiredFigureCount = 0`, with all DesignUnit IDs in `completedFigureUnitIds`. `.mmd` paths, diagnostics manifests, syntax success, or a `save_mermaid_artifact` count never contribute. A required render failure blocks all Word creation, including a working skeleton. An optional owning-module orientation figure is additional and satisfies no base slot. Keep each successful render and its unique target H2/H3 heading in the ledger; only after all render transactions and prose readiness pass may the initial text-only working skeleton be created, and insertion starts only after its body audit passes:

