# `/spec` Skill 重构验证记录

> 历史记录：以下对应简化前的方案与当时验证，不是当前 Skill 的操作要求或本轮验收结果。当前结果见 `validation/简化验证记录.md`（相对 Spec 模块根目录）。

日期：2026-09-08。范围：当前工作区源码、Mac 本地开发构建与浏览器交互。扩展版本保持 1.2.17；本轮未生成、安装或发布交付 VSIX。

## 实现结论

内置 `/spec` 经原有命令钩子按需加载私有 Skill，随后进入普通 Agent。删除旧 Spec 的执行器、阶段状态机、专用模型调用、预算检查、提问适配和文档阻塞规则。保留原命令标记、当前对话及流程介绍布局。内置命令不绑定模型，用户已有通用命令模型覆盖继续生效。

资源随 CLI 内嵌，仅执行命令时准备到内容版本缓存；加载器不读取任务、不解析文档、不调用模型。三次确认由 Skill 要求模型通过正常 question 执行，不构成程序强制批准门禁。旧任务目录与 task.json 不迁移写入、不执行旧批准；恢复方式由模型读取历史并整理新材料。

## 普通 QA 隔离审查

- 对照本轮修改前源码，`session/prompt.ts` 只删除专用执行器导入及执行分支，恢复原命令钩子后进入标准 prompt；没有新增 Spec 消息分流、模型选择或取消判断。
- 插件接口删除旧命令执行上下文与 execute 扩展，保留标准 parts 钩子。工具目录、权限、普通 QA 发送、服务器接口和 webview 协议均未增加 Spec 能力分支。
- 仅命令名与内置模板标记匹配时加载 Skill；同名自定义命令、普通文字引用与非 Spec 命令不加载。资源不注册到全局 Skill 列表。
- 普通消息、Word/RAG 讨论及 Spec 请求使用相同原生工具目录。前端 Word 引用仍使用既有文件引用格式；不改变普通 Word 问答附件契约。
- 流程介绍只改职责文字。候选选择、查看与关闭介绍不会产生模型请求或任务。当前会话保留历史，不能保证后续模型回答完全不受历史影响。

## 交互证据与反例

浏览器套件从真实 HTTP `/spec` 命令进入 SessionPrompt 和原生 Agent。前端使用当前 ChatView 与 SessionProvider，问题读取及回答使用现有扩展处理器和正式 HTTP 接口；浏览器实际点击选项。只将模型响应脚本化，不手工补造后端缺失的工具消息。

两条路径分别覆盖三次确认，以及需要修改、重新确认、面板重开恢复和暂停。关联问题请求的 messageID、callID 来自实际工具消息。反例移除该消息但保留问题请求时，卡片不可见；恢复真实消息后才可以点击完成回答，能够检测此前遗漏展示关联的问题。

后端另行覆盖关闭、空回答、中止及下一条消息恢复。Word 固定文件包含目录域、交叉引用、合并表格、修订和 DMA 停止条件缺口，验证通过原生读取及结构工具处理，没有调用已删除的自动阻塞解析器。这些测试不证明真实模型能正确判断图文含义或遵守确认边界。
