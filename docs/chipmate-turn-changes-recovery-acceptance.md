# 本轮修改自动恢复修复与验收记录

日期：2026-09-14。范围：普通 Agent 的侧边栏、编辑器聊天和 Agent Manager；保留同一界面生命周期中的状态，不增加跨重启持久化、独立 DeepSeek Harness 支持或新的后端接口。

## 修复内容与根因

旧实现把只读差异请求与文件写入共用活动会话检查，后台会话收到更新后读取被拒绝；成功读取又不清除旧错误。展开状态放在聊天行内，重新挂载会丢失。

只读请求现在先查询请求会话的权威目录，再读取指定轮次。目录未知时等待元数据返回，不使用其他会话的目录推断归属。后端原有目录校验继续执行。撤销与恢复在预检前后检查当前会话、连接代次，并复查已有操作权协调器的 token；同时检查记录版本及未保存文件。Agent Manager 保留既有 unmanaged 模式，本次未扩大操作权协调器的覆盖范围。

记录控制器保存展开轮次、所选文件及摘要、详情各自的请求标识。非当前会话更新只标记待刷新，切回及重连自动读取；迟到响应、其他轮次和旧版本不能覆盖展示。读取成功只清除相应读取错误，保留真实写入冲突；切走后已提交操作按原目标收尾，不重放。删除记录和关闭界面释放订阅与请求状态。

真实窗口进一步发现并补齐了两处问题：历史页会卸载整个聊天组件，因此将控制器提升到三个入口共用的稳定外层，并让嵌套聊天复用上下文；可用状态改为响应式信号，防止切回后整轮撤销按钮仍保持禁用。

## 真实窗口验收

环境：本机 macOS arm64，VS Code 1.134.0，独立用户目录及扩展目录，源码清单版本 1.2.21；该版本号来自工作区已有清单，本次没有改版本或生成 VSIX。使用固定响应的本地模型服务，经正式聊天入口、真实 Provider、SDK、HTTP 与工具执行器生成两份 40 行文件的第 2 行、第 25 行修改。模型夹具只控制输入结果，不补造审阅消息、记录或写入结果。

共享开发目录中的 CLI 曾被并行构建替换为 Linux ELF，导致 macOS 重载报 `spawn ENOEXEC`。后续验收使用独立复制并核对 SHA-256 的扩展资源，以及 `TESTING.md` 定义的源码后端入口；未覆盖并行构建的产物，也未安装或替换日常插件。

| 正式入口 | A→B→A 往返 | 错误会话提示 | 串会话展示 | 手动重新打开/刷新 | 自动化平均往返耗时 |
|---|---|---|---|---|---|
| 侧边栏 | 10 | 0 | 0 | 0/0 | 3231 毫秒 |
| 编辑器聊天 | 10 | 0 | 0 | 0/0 | 68 毫秒 |

三处入口均核对原文件选择及展开差异；侧边栏和 Manager 在每次切回后还核对整轮撤销按钮恢复可用。编辑器通过原生标签切换，侧边栏和 Manager 通过各自会话标签切换，因此耗时不可直接横向比较。

三处入口分别通过真实审阅控件撤销、恢复整轮修改，并独立核对磁盘：撤销后两处修改恢复原文，恢复后逐字等于操作前内容。另从编辑器操作 A，在 Manager 停留于 B 时产生真实后台更新；切回 A 后自动显示已撤销状态，保留文件展开，恢复时也自动更新，无需重新打开或手动刷新。

## 人工介入与验收边界

故障人工基线是切回后额外重新打开审阅、恢复所选文件。验收目标是错误会话提示、串会话及手动恢复均为零。脚本记录的往返耗时包含控件定位与等待，不能当作人工耗时。没有同一操作人员在旧版/新版的计时对照，不声称人工精力降低至少 80% 已实测达成。

未验证用户现场机器、日常 VS Code profile、已安装版本及实际部署模型；本次不包含打包、发布或插件升级。真实验收覆盖既有两轮修改在三个正式入口中的展示和操作，不等同于每个部署模型的端到端能力验收。
