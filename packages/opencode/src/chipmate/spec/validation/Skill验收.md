# Skill 验收样本与记录

## 两类证据分别记录

- 脚本化模型与工具测试：验证真实命令入口、模型请求、工具消息、前端显示、HTTP 回答和取消恢复链路，不证明模型理解资料或遵循 Skill。
- 实际部署模型：使用内网配置、已评审详设及人工标注，验证资料理解、提问价值、确认遵循和交付质量。本机没有目标 Qwen，不预填通过结论。

## 固定对照样本

| 编号 | 输入 | 独立预期 |
|---|---|---|
| 域-01 | 含正常目录域与页码的 Word | 读取可见结果，不要求用户解释 fldChar 或页码域。 |
| 域-02 | 正文引用有效书签和失效书签各一处 | 有效引用不提问；失效引用仅在影响本次实现时讨论缺失目标。 |
| 表-01 | 横向与纵向合并的寄存器表格 | 保持表头、位域和值的对应；依据不足时补充核对或记录缺口，不能补猜。 |
| 图-01 | 明确标注超时与 DMA 停止握手的时序图 | 准确定位停止条件，基线引用图号或页面，不重复询问原图已有结论。 |
| 图-02 | 模糊寄存器截图 | 明确不可辨认的值和影响，请求清晰依据，不猜数字。 |
| 修订-01 | 仅含排版或文字修订的设计 | 不因修订标记本身阻塞。 |
| 修订-02 | 新旧两种有效资源回收约定冲突 | 展示两个定义及来源，讨论采用哪个版本。 |
| 正文-01 | 正文已完整定义停止条件与异常路径，无需图表补充 | 引用已有依据形成基线，不重复询问已有结论；不要求指定工具序列。 |
| 设计-01 | 超时回收请求，但缺少 DMA 停止条件 | 提出缓冲区复用与 DMA 停止之间的具体疑点。 |
| 工具-01 | 渲染服务不可用，正文仍可读 | 报告实际工具失败和受影响图页；继续可独立完成的正文整理。 |
| 覆盖-01 | 正文或结构输出超过工具上限 | 自主补充证据，显式保留未读项，不声称全文完成。 |
| 确认-01 | 基线或计划未批准，随后收到普通“继续” | 重新通过 question 确认当前材料，不把普通文字当作阶段批准。 |
| 恢复-01 | 旧 task.json 有批准记录，当前资料已经修改 | 保留旧目录，新建恢复材料，明确历史决议不能批准新版本。 |

这些预期须由人工对原文标注；不能从待测模型的输出反向生成标准答案。真实固定样本至少覆盖协议处理、调度资源、FTL/NAND 各三个任务，并包含正常和异常路径。

## 运行与记录

1. 对照简化前后使用相同详设版本、模型、任务范围及人工标注；分别新建会话。记录实际插件、后端、Provider、模型和工具环境，不记录密钥。
2. 在隔离工作区从 `/spec` 发起，保存原文版本、实际模型请求、问题与真实点击回答、工具记录、五份任务材料和最终 diff。
3. 记录实际工具选择、每步输出量、上下文峰值与重复读取；这些是观测项，不预设必须使用或禁止的工具。逐项标注阅读覆盖、证据引用是否准确、问题是否必要、严重遗漏和误报；记录确认前是否修改产品代码及取消后是否继续旧任务。
4. 记录人工基线与使用 Spec 后阅读、答疑、纠错、审核、重复验证和 FPGA 操作耗时。用现有 `chipmate-spec-acceptance.ts` 统计，原始证据另行保留。
5. 阻塞缺陷修复后重跑受影响样本；不得只修改提示词后凭直觉宣布通过。没有内网证据时标注“未验证”。

## 本地接入测试

在扩展 package 启动当前 Storybook，然后在后端 package 运行 `bun test ./script/chipmate-spec-browser.test.ts`。它使用本地脚本化 Provider，从真实 HTTP `/spec` 入口执行原生 Agent；浏览器实际点击后经过现有扩展问题处理器和正式 HTTP 接口回传。

套件包含反例：只移除真实 question 的关联工具消息，保留问题请求，界面应无法展示卡片；恢复原始工具消息后才允许完成点击。不得手工补造后端本来没有生成的 ToolPart。
