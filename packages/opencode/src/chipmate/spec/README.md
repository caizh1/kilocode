# `/spec` 按需加载 Skill

在当前对话显式发送 `/spec`，由普通 Agent 根据 SDD 流程理解详设、整理基线、规划任务并开发验证。选择候选和查看流程介绍不会开始任务。

## 使用与模型

输入 `/spec` 并附上详设或说明本次范围。基线、计划和交付通过现有原生 question 弹框分别确认，以真实回答为依据。修改后重新确认相关内容，暂停时保存进度。这些是 Skill 行为要求，不是程序强制批准状态机。

内置命令默认跟随当前选择的模型，不检查型号。建议在内网实际部署的 Qwen 上完成样本验收；已有 `command.spec.model` 覆盖仍按原有规则生效，需要跟随当前模型时由用户清除覆盖。普通 Agent 的权限、模型调用和上下文管理保持不变。

## 自主执行与质量原则

Skill 只说明阶段目标、交付和质量原则，不指定文档阅读工具、调用顺序、读取行数、图页数量或分工方式。模型根据任务与现有工具能力决定如何获取充分依据；工具本身的权限和输出约定继续有效，没有新增工具黑名单。

保留重要事实、推导前提、原文入口与未读缺口，不以摘要、转换成功或记录存在代替理解。只对真正影响实现或验收的问题请求决议，不因目录或修订标记本身阻塞，不补猜关键值。来源变化或发现矛盾时核对受影响内容，不机械重复已经掌握的资料。

没有修改文档工具的大输出行为、转换实现或公式渲染；模型仍可能自主选择相关工具。指引简化不保证上下文不再增长，也不证明真实模型已达到质量目标。

## 任务与迁移

任务根目录继续由 `ProductProfile.project` 解析到当前工作区产品目录下的 `artifacts/spec`。保留资料与决议、执行基线、开发任务、验收记录、进度五份中文材料，按需要保存进一步的证据，不要求图页专用交接或批次目录。

旧任务、缓存、日志、代码改动和历史材料保留。旧 task.json 只作历史资料；恢复旧任务时在新目录核对当前依据和待办，不执行旧状态机或继承旧批准。

主 Skill、三份阶段参考与五份模板随 CLI 内嵌，仅执行内置命令时按内容哈希准备资源。旧资源缓存不删除，新命令使用新版资源；既有聊天历史不会自动改写。建议新会话进行版本效果对照；恢复工作时保留已有材料和进度。

## 普通 QA 边界

普通消息、Word 问答、RAG、其他命令和 Skill 不增加 Spec 判断。内置命令仍通过模板标记识别，不进入全局 Skill 自动发现列表；命令列表和介绍不扫描任务或调用模型。同一对话历史仍可能影响后续回答。

## 验证

本轮实现、接入证据与未验证项见 [简化验证记录](validation/简化验证记录.md)，真实模型样本见 [Skill 验收](validation/Skill验收.md)。[早期重构](validation/重构验证记录.md)和[旧图页方案](validation/图页阅读验证.md)仅记录历史，不是当前操作要求。

脚本化模型仅验证命令、工具和消息接入，不证明模型会自主选择合理方式或正确理解设计。内网使用同一已评审详设、模型、范围和人工标注对照调用、上下文峰值、有效疑点、遗漏与耗时，源码测试不能代替目标环境验收。

保留既有 `script/chipmate-spec-acceptance.ts` 和 `evaluation.ts` 的统计口径：条款映射覆盖 100%、证据准确率至少 95%、固定样本严重漏检零、阻塞误报不高于 5%、实际人工耗时减少至少 80%。未完成真实测量时不宣称达到目标。

本轮不修改版本、不打包、不发布。
