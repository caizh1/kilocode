# OpenSSD 原始 Code QA 回归

## 结论

2026 年 8 月 1 日将代码注释链路从大体量 JSON 和最多三轮恢复，收敛为两轮临时只读 `code` 会话：第一轮理解函数并生成 comment-only Diff，第二轮重新阅读源码后通过、修订、判定无需注释或报告无法解决的证据冲突。模型固定为 `chipmate/deepseek-v4-flash`，OpenSSD 仓库全程只读。

最终一轮 3 个函数全部完成，6 个会话全部正常返回，无 120 秒超时。平均每个函数耗时 52.6 秒，最慢单会话 49.4 秒；相较旧 JSON 链路的平均 182.9 秒与最多三轮恢复，超时和机械格式失败已明显缓解。

这不是发布通过结论。人工复核发现 `IssueNandReq` 的函数说明把所有分支称为“异步 NAND 命令”，但 `RESET` 与 `SET_FEATURE` 实际分别落到 `V2FResetSync` 和 `V2FSetFeaturesSync`。第二轮模型没有抓住这一处明确事实错误，因此当前结果只能标记为“未验证”。

## 格式与安全修复

- 不再要求模型生成 JSON Schema、证据数组或七类理解字段，正文优先读取原始 Code QA。
- 只保留第一轮与独立复核两轮，不再用第三轮仲裁掩盖首轮失败。
- comment-only Diff 可拆为一至四段，不依赖模型容易写错的文件头与 hunk 行数。
- Diff 围栏内漏写 `+` 时，只识别合法注释语法；源码锚点仍必须对应当前函数的 Tree-sitter 安全语句。
- 锚点按去前导空白后的完整源码行和源码顺序定位，再使用源码真实缩进渲染；宏续行仍拒绝。
- 最终候选仍需通过注释语法、重复、TODO、代码注入、锚点和非注释 token 完全一致校验，并在 VS Code Diff 确认后才能应用。

## 质量判断
