# 开发计划

依据已确认的基线和当前代码形成开发任务，确保关键结论有可核对的设计依据。来源变化、记录冲突或理解不足时核对受影响部分，不能仅凭摘要虚构实现。

## 计划应说明

- 每项任务的目标、交付物、依据条款、依赖、修改范围及完成条件。
- 如何验证预期行为，预期来自哪项已确认设计、既有测试或硬件约定。
- 哪些验证可以自动完成，哪些依赖交叉编译环境或人工 FPGA 操作。
- 未决问题影响哪些任务；不依赖该问题的工作如何继续。

结合实际仓库、接口和已有改动确定范围，识别冲突与必要依赖。任务粒度、探索方式和分工自行决定，遵循工作区与工具权限；默认在当前工作区完成，不覆盖其他人的工作。

展示可审阅的计划和验证方法，按主指引请求第二次确认。修改计划时说明差异并重新确认受影响部分；计划批准不等于授权合并或发布。
