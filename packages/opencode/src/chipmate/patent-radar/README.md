# Patent Radar 本地引擎

本模块只在 ChipMate 本机进程中运行，负责扫描嵌入式 C/C++ 和首版支持的设计文档、提取带源码定位的创新候选、调用独立 Patent Server 检索公开专利，并生成逐项证据矩阵与本地报告。

## 数据边界

- 工作区文件、证据片段、候选、人工评审和导出报告保存在 ChipMate 本机数据目录的 `patent-radar/<workspace fingerprint>/` 下。
- 发往 Patent Server 的请求只包含候选的必要技术特征、分类提示、日期界限和检索参数，不包含完整源码、完整设计文档或本地路径。
- 短代码证据只发送给用户在专利中心选定的已连接 Provider 模型；内网 HTTP 和 HTTPS 均受支持，未能确认端点时扫描直接失败。
- `uploadFullSnapshot` 是默认关闭的预留开关；首版服务端没有源码上传接口，因此即使误开启也不会上传完整快照。

## 结论门禁

v2 先建立带编译 Variant 的确定性关系图，再通过机制卡和重叠 bridge 单元进行跨文件合成。语义相似只使用现有本地 Embedding 索引发现观察项，不能晋升技术候选。每个候选还要经过独立原文复核；运行记录、证据分片、机制批次、bridge、复核和专利矩阵均保存检查点。

代码和专利排序均不使用 Rerank。Patent Server 固定以 BM25、向量和引用扩展的 RRF 融合分数作为排序真源，即使环境中意外存在 Rerank 端点也不会调用。

只有语料、权利要求覆盖、向量覆盖和 generation 状态全部通过门禁，且逐项引用能够回溯到 Patent Server 返回的真实段落时，才允许输出 `review-ready`。服务故障、矩阵缺格、模型引用不一致或语料不完整统一降级为 `insufficient-evidence`。

`review-ready` 的含义固定为：当前语料和截止时间内暂未发现一份更早文献完整公开全部必要技术特征，仍需人工专利检索。它不是新颖性概率、授权判断、无冲突判断或不侵权意见。完成真实 gold set 验收前，整个发现流程固定标记为实验性。

证据包会按候选哈希稳定抽取约 20% 的候选，额外生成不含首审结论的 `blind-review.json`。第二位评审人只填写其中的 `reviews` 数组，再通过 VS Code 的“Patent Radar：导入盲审结果”命令导回；同一候选出现 `worthy` 与 `reject` 分歧，或任一评审选择 `needs-arbitration` 时，界面会明确提示人工仲裁。

## 当前未验证边界

真实官方历史包和增量包、至少 10 个嵌入式项目、50 个人工技术点（其中至少 30 个跨文件点）尚未在仓库内提供。因此实现完成只能证明代码路径与确定性门禁可运行，不能宣称已经达到总体召回 90%、跨文件召回 85%、主队列 75% 精度、冲突 Recall@50 95% 或人工工作量减少 80%。
