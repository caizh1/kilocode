# VS Code 定时任务

在已打开项目的 QA 对话中，可以让 Agent 创建、查询、修改、暂停、恢复和删除定时任务，也可以要求立即执行、查看历史或停止某次运行。Ask 模式可管理计划。创建时默认继承当前 Agent、模型和 60 分钟超时。变更执行 Agent 使用独立权限请求。

通过 ChipMate 工具栏的时钟入口或命令面板中的“ChipMate：定时任务”打开统一管理界面。管理页与 QA 工具共享后端记录。表单支持一次性、固定间隔、每天、工作日、每周和每月计划，保存前可预览未来五次时间。

任务绑定账号、配置存储范围和项目目录。VS Code 必须保持运行，项目必须打开且受信任。关闭窗口或退出登录会撤销执行资格。重开后记录错过的计划，未来时间继续执行。已有 worktree 可作为项目目录使用。

每轮可新建会话，也可继续同项目已有会话。继续会话使用正常消息队列，保留人工消息顺序。审批和提问显示“等待用户”，通过“处理请求”进入结果会话进行操作。暂停只影响未来及未开始的执行，停止本次会精确取消对应轮次。删除会撤销未来计划并取消在途运行，运行历史继续保留。

任务按目录串行执行，同一账号配置范围最多同时运行两项，每个任务最多保留一项未结束运行。排队上限 30 分钟，主动执行超时可设为 1～240 分钟，等待用户上限 24 小时。运行中下一次计划到点时记录跳过原因。

调度记录保存在现有 SQLite 数据库的 ChipMate 专属表中。数据库事务和唯一索引负责计划领取去重，执行租约负责窗口退出与异常恢复。已开始或结果不确定的运行由用户确认后手动重试。每次工具执行前检查有效租约，定时运行及其子任务隐藏计划管理工具。

接口在 `/scheduled-task/` 下提供 `register`、`tick`、`command`。接口类型及事件由标准 SDK 生成流程维护。`command` 的操作包括 `create`、`list`、`get`、`update`、`pause`、`resume`、`delete`、`run_now`、`runs`、`get_run`、`cancel_run` 和 `preview`。任务修改带版本，创建和手动执行带幂等键。

## 验证范围

自动测试覆盖时间规则、SQLite 领取、幂等、版本冲突、错过记录、过期租约、取消队列顺序，以及从真实 QA 消息入口经过工具创建、后台执行、提问回答到结果持久化的路径。无头浏览器补充验证表单创建、预览、手动执行和窄布局。

macOS 真实 VS Code 开发宿主已完成 Ask 对话创建、修改为一分钟、暂停跨过触发时间、恢复、关闭管理页后定时触发、打开提问、点击提交、查询结果以及重启后读取历史的闭环。验收使用源码编译的 CLI、实际 Webview、正式工具与回答接口。外部登录及模型使用隔离的本地服务夹具，模型请求返回确定性的工具调用。

该单样本运行只产生一条记录，计划领取延迟为 3.671 秒，最终用户消息、执行会话与运行记录匹配，结束后无待回答问题或权限请求。完整扩展编译和相关回归通过。Windows 目标环境、实际部署模型的自然语言准确率，以及减少 80% 人工时间的生产力指标仍待验收。
