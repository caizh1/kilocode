# 小屏修改记录伸缩栏验收

本次仅调整普通 Agent 的聊天展示和前端记录订阅，覆盖侧边栏、编辑器聊天及 Agent Manager。撤销后端、持久格式和接口保持既有契约；不接入独立 DeepSeek Harness。不提交、不打包、不发布。

## 实现

- 移除普通聊天的 `WorkingIndicator`，并将没有可见修改结果的虚拟消息行及其间距归零。保留真实历史消息的虚拟滚动高度。
- 输入框上方仅保留 28×16px 的透明三角按钮，图形 8px。记录栏关闭时高度为零，内容不可聚焦；展开一行状态为 33px，最多两行且不超过 56px。
- 记录栏使用正常 flex/grid 文档流和约 150ms 高度过渡，不覆盖对话。VS Code 减少动态效果设置优先于操作系统偏好。
- 共用记录控制器持续订阅当前轮次更新；按实际执行用户消息关联，复用队列归属逻辑。会话、轮次、版本和请求标识共同限制响应消费，历史事件不会打开当前伸缩栏。
- 正常结束、停止及错误仍等待后端收尾状态。完成结果留在所属轮次正文底部，默认仅显示摘要、审阅和撤销入口；文件列表与差异按需展开。只读镜像不增加三角。
- 图标点击保留输入焦点和草稿；键盘支持 Enter、Space 和可见焦点。隐藏原生成状态后，输入框停止按钮及原有授权、提问和错误入口继续工作。

## 组件与真实入口证据

浏览器测试直接挂载共用 `ChatView`，只有扩展消息传输使用固定夹具。验证 280/360px 宽、480/640px 高组合；收起控件不超过 16px，抽屉高度为零，展开仅扣除实际抽屉高度，输入框位置和尺寸变化不超过 1px。历史滚动偏移不超过 2px，前端空闲但后端仍在整理时不出现可撤销结果。覆盖浅色样式、125% 放大、多行草稿、指针焦点和键盘操作，以及 VS Code 动效优先级。

反例检查会重新引入 32px 隐藏抽屉占位及旧状态节点，正常布局断言能识别。记录单测覆盖迟到响应、旧版本、其他轮次、收起后的状态更新和重复撤销请求。队列归属复用现有测试，未在测试中复制生产算法。

真实入口使用隔离的 macOS VS Code 开发窗口、新 Git 工作区和本地确定性模型服务。模型通过正式 `write` 工具修改文件两处，并通过模型流输出 50 段长回答；后端记录和界面操作没有使用预置修改记录。实际点击三角、停止、审阅、整轮撤销、差异块撤销、单文件撤销及恢复，并读取真实文件核对。
