# 高可信代码注释定标结论

## 结论

2026 年 7 月 31 日仅针对双会话独立复核策略重新执行了 5 个固定 QEMU 函数。旧的 A/B 总分受交互工具和模型认证环境污染，不能作为有效质量结论；本轮已排除这些因素，并将内容质量与完成率分开统计。

本轮完成样本的内容平均分为 86.0，估算事实正确率为 97.1%，严重幻觉为 0。内容本身达到 85 分线，但最终可用结果只有 2/5，标准两轮直接完成只有 1/5，因此功能仍为“未验证”，不能进入 50 函数发布验收。

## 去干扰条件

- 所有生成与复核会话均固定使用 `agent=code`，不是 Ask 或 Ultra。
- 固定实际模型为 `chipmate/deepseek-v4-flash`；请求返回的 provider/model 不一致时立即失败，禁止回退。
- 明确关闭 `question`、终端、编辑、网络、任务和其他交互或副作用工具，只保留只读检索工具。
- 每轮使用新的临时会话；成功、失败和超时后均删除会话。
- 先执行不计分连通性预检，确认实际返回 `chipmate/deepseek-v4-flash`；失效的直连 `deepseek` 凭据和未登录的 `chipmate` provider 均未用于正式重测。
- 内容评分只覆盖 `ready` 样本；`unresolved` 不记零分，而是单独计入完成率和失败原因。
- 服务日志中本轮没有 `question.asked` 或 asking 事件，超时不再是无人回答交互问题导致。

`qemu_parse_fd` 的返回范围、错误哨兵、`errno` 顺序约束和调用方判错方式均能由源码支撑；主要扣分是函数级说明复述了部分直接可见检查。`aio_task_co` 正确覆盖在途计数、首个失败、任务释放和唤醒握手，但函数级说明又分别配了三条行内注释，阅读负担偏高；结构化理解中“`task->ret` 供调用方经 status 间接查询”没有限定为“首个负返回值”，属于轻微事实不精确，不构成严重幻觉。

## 发布判断

旧的 54.6/31.6 平均分作废，不再用超时或环境失败拉低内容分。本轮证明模型在完成输出时可以达到较高事实正确率，但现有长 Schema、最多六次检索和三阶段恢复仍让 3/5 样本无法形成可应用结果，距离自动恢复后完成率不低于 95% 的门槛很远。

下一步必须缩短输出协议、限制不必要的仓库检索，并把 `verification.conflicts` 的语义改为只保留未解决冲突；完成后重新跑同一组 5 函数。通过前不得宣称达到高可信或减少人工 80%。
