# 普通 Agent 按轮审阅与撤销：实现及验收记录

验收日期：2026-09-08。范围是当前源码和 macOS Apple Silicon 上的 VS Code 扩展开发窗口；本轮不包含 VSIX 打包、发布或目标 Windows/Linux 安装验收。

## 用户流程和完成条件

普通 Agent 的侧边栏、编辑器聊天和 Agent Manager 共用一份后端修改记录。每个用户消息标识对应一轮；同一工作目录中的所属子任务归入父轮。排队消息由现有队列选择当前用户消息后分别计轮。独立 DeepSeek Harness 不接入。

每轮列出文件、变更类型和增删行数，点击文件按需读取差异。整轮、单文件和文本差异块均可撤销；新增、删除、重命名、二进制文件按文件处理。保留聊天记录，显示部分撤销或已撤销，并可恢复最近一次尚未恢复的撤销操作。现有“回退对话”保持独立。

停止保留已发生的修改。状态依次经过正在停止、正在整理修改，等待本轮受控工具的实际执行和记录写入全部结束后，才能显示可撤销状态。例如“本轮已停止 · 修改了 1 个文件”。模型没有生成最终摘要也不影响记录。错误结束与正常结束共用收尾流程。

## 数据与操作契约

- 执行前等待工作区基线快照完成，将原始树保存为会话轮次专属 Git 引用，持久写入轮次记录和活动租约后才执行工具。明确的编辑工具目标在执行前另记内容指纹及快照遗漏原因。
- 工具执行后和轮次结束时核对实际快照。原始树及最终树由 `refs/chipmate/turn-changes/` 引用保留，不依赖快照的七天可回收对象窗口；删除会话时释放引用和记录。无快照的只读记录也能正常释放。
- 清单、文件差异和撤销接口在 `/session/:sessionID/turn-changes/:messageID` 下，文件和差异块使用后端标识。修改请求绑定版本及操作标识，拒绝错误会话目录、错误文件、旧版本和操作标识复用。
- 撤销以该轮修改后内容为基准，将原始内容反向三方合并到当前文件。恢复使用操作日志中的前后内容反向合并。所有目标先完成冲突、范围、内容和权限预检，再创建持久操作日志并写入；每次写入前及全部写完后均核对实际内容。
- 工作目录锁串行化轮次登记、收尾、撤销及恢复。重复请求返回已提交结果；异常重启通过日志回滚未完成的已知写入。日志以外的后续编辑不会被强制覆盖，无法恢复时保留日志并拒绝继续写入。
- 扩展在发起修改前检查目标文件的未保存文档；三个聊天入口通过既有会话操作权协调器使用相同接口，操作权切换会返回关联错误，避免按钮一直等待。
- 进程异常退出后的活动记录标记为未结算。下次读取核对实际快照，保留不可安全撤销的原因，不把缺失收尾误报成没有修改。

## 支持条件与边界

默认需要已有 Git 工作区、开启快照且目标原始内容完整。不自动初始化用户仓库或改变快照设置。基线遗漏、符号链接、子模块、无法确认归属、执行期间人工编辑、并发会话等情况保留可得记录并禁用撤销。已知仍运行的后台进程或交互终端也阻止历史撤销。

普通受控文件工具和前台终端工具归入轮次；终端命令可撤销范围是快照完整收录的工作区文件。任意脱离受控生命周期的系统进程、工作区之外的副作用以及快照排除目录中的任意终端写入不提供完整归属保证。显式编辑快照遗漏文件会展示具体不可撤销原因。

文本差异块需要可无损解码及编码一致；覆盖 UTF-8、BOM、CRLF、无末尾换行和 UTF-16 夹具。超出差异大小限制的文件仅按整文件处理。删除及重命名与后续修改冲突时拒绝自动撤销。内容相同且权限未变的二进制文件可精确还原。未验证 ACL、扩展属性、多窗口未保存缓冲区之间的同步或任意外部进程写入。

## 验收样本和质量口径

目标用户是需要审阅或丢弃普通 Agent 某一轮修改的开发者。人工基线是阅读工具及聊天记录、定位文件和修改范围、区分后续编辑、手工还原、重新核验。目标是减少这些步骤的人工时间至少 80%，不能用按钮数量或自动化测试耗时代替人工测量。

固定夹具包括 40 行、两处相隔较远的 C/C++/文本修改，多文件冲突，后续人工修改和后续轮次，以及新增、删除、重命名、二进制、私有文件权限和不同编码。质量门槛为：支持范围内不遗漏已落盘目标，目标外内容不变，任何预检冲突不得产生工作区写入，重复操作不重复应用，中断后不提前开放撤销。固定测试中的安全断言必须全部通过；不能据此推算真实项目的误报率、漏报率或总体代码覆盖率。
