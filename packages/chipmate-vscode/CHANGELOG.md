# ChipMate 发行说明

## 1.2.8

相较 1.2.7：

- 专利中心现在允许直接配置受控内网中的 HTTP Patent Server 地址，连接测试与 Patent Radar 检索使用同一地址规则，不再强制部署 HTTPS 证书。

## 1.2.7

相较 1.2.6：

- 内网版本不再在模型选择器、Agent Manager 或自定义 Provider 模型管理中展示 GLM 5.2 与 Doubao 系列；已有选择会保留配置并自动回退到下一可用模型。
- 会话精简状态卡现在持续显示已等待时间，并按准备、生成、分块、归并、重放和提交展示真实阶段；存在多个确定工作单元时同步显示完成数和当前阶段百分比，单次长思考请求继续使用动态进度条，不伪造百分比或预计时间。
- 当前思考模式未生成有效摘要并自动回退时，状态卡会明确提示正在关闭思考后重试，并从第二轮准备阶段重新计数；成功、失败或中断后显示本次精简的总耗时。
- 修复 Qwen/vLLM 流式工具调用先返回工具 ID、后续分片才返回工具名时错误中断推理的问题；插件现在会等待后续分片补齐工具名，参数分片仍会完整合并，且工具只执行一次。

## 1.2.6

相较 1.2.5：

- 可将当前会话一键转到 VS Code 主编辑区使用；同一会话只保留一个主区标签，并可通过“收回侧栏”完成确认式交接。
- 侧栏与主区共享消息、草稿、附件、未决交互和会话身份，通过单一可写 owner 与代次 token 阻止重复发送和旧界面写入；顶部标签同步增强当前会话的选中效果。
- 修复首次打开或恢复 ChipMate 侧栏时因会话操作权未完成初始化而持续显示“初始化中”的问题。
- 修复覆盖安装后自动恢复旧会话时，历史模型与当前默认模型持续来回切换的问题；历史会话继续从历史用户消息恢复模型，共享草稿不会改写会话元数据。
- 普通会话切换现在会等待当前完整草稿的持久化 ACK；持久化失败或超时时不切换标签，并保留文字、附件、Review Comments、模型选择与滚动位置，迟到快照不再覆盖未确认输入。
- ChipMate DeepSeek Harness 在主区交接时复用原 taskId，并等待旧官方客户端确认释放后再转移唯一 lease，不回退为普通 QA。
- 新增独立的 UFS Reviewer Agent，通过只读多 Session 流水线完成范围冻结、专项审核、对抗复核、证据校验和架构双门禁，并可把选中问题交给同一会话的 Code Agent 修复。
- 在会话 Token 用量旁展示 New API 按请求日志结算的人民币实扣费用，并按主会话、子代理、模型和实际分组汇总结算状态。
- ChipMate DeepSeek Harness 顶部只显示当前官方会话标题，不再残留普通 Agent 的标题、令牌统计或会话操作。
- 修复系统休眠、Extension Host 短时卡顿或调试暂停后，DeepSeek Harness 生命周期 Supervisor 误判租约过期的问题，并增强 Windows 正常关闭诊断。
- 修复 Agent Manager 中官方 DeepSeek Harness Cordis 客户端被 Webview CSP 阻止后持续黑屏的问题。
- 顶部“精简会话”和 `/compact` 现在统一先展示风险说明与知情确认；取消、切换会话、断线或进入忙碌状态均不会发送压缩请求。
- 会话精简现在会在时间线中明确保留进行中、成功、失败或中断状态；按 `Esc` 或停止按钮仍按官方机制中断当前回合，但不会再因进度卡消失而被误认为精简完成，自动精简也会标明来源和最终结果。
- 会话压缩不再把模型输出固定限制为 2048 Token；完整 worker 请求会在并发发送前按上下文预算确定性拆分，超长正文与推理内容按连续片段完整保留，未知容量模型返回上下文超限时只继续细分失败单元。当前思考变体未生成有效摘要时会丢弃整轮结果，并在模型支持时使用同一模型的无思考模式完整重试一次；手动压缩会继承最近真实用户消息中受当前模型支持的思考变体，避免空摘要、半截摘要或错误压缩边界。
- 修复内网包把出厂 DeepSeek 写入高优先级运行时配置、导致“设置 > 模型”保存的全局模型无法生效的问题；DeepSeek 现在只作为未配置用户的打包默认值，保存 Qwen 后新对话与重启后均使用 Qwen。
- 恢复官方模型优先级：手动选模和模式专属模型继续显式覆盖全局默认，普通新会话继承全局默认，历史会话从历史用户消息恢复。
- 不再自动清理或迁移 `model.json`；旧版写入的自定义会话模型元数据与迁移标记仅被忽略，不删除用户数据。

## 1.2.5

相较 1.2.4：

- ChipMate DeepSeek Harness 按平台使用未经修改的官方模式：Windows x64 使用 `standard`，Linux x64 使用 `minimal`；Windows 不再因缺少 `/bin/bash` 无法启动，已有匹配模式的官方会话继续原样恢复。
- 启动前只展示已在 ChipMate 中配置直连 NewAPI 地址和直接 API Key 的 DeepSeek Provider；默认选择会避开不可用的内置 Provider，启动失败前也可重新选择可用 Provider。
- 同一 Provider 切换模型不重启官方 DSH；跨 Provider 切换按任务状态执行确认和正常 SIGTERM 重启，不热改正在运行的凭据环境。
- 修复官方 DSH 监听地址已写入日志却仍持续等待，以及首个窗口租约尚未稳定时 Supervisor 误判 `lease-expired` 并强制终止进程的问题。
- 修复模型默认输出预算与 262,144 上下文冲突导致首轮请求必然失败的问题，并在事件流瞬时断开后复用同一进程和 Session 完成重连与官方历史恢复。
- 往返切换普通 Agent 与 ChipMate DeepSeek Harness 时复用已验证的运行时、物理事件连接、官方 Session 和会话投影，不再重复下载、全量校验或重新建立后台服务。
- 在 DSH 输入区增加官方模型公布的思考强度选择；当前 DeepSeek 适配器可选 `Off`、`High` 和 `Max`，选择继续由官方 `session.selectModel` 提交，不修改官方 Prompt、工具或 Agent Preset。
- 修复空白 QA 会话在确认期间生成 Session ID 时静默取消 DSH 启动的问题；确认后会进入 DSH 页面，真正切换到其他既有会话仍会安全取消。
- 修复 Windows 将规范 Skill 文件权限报告为 NTFS 合成权限后触发 `installed skill snapshot sha-256 mismatch`、导致 UML 无法安装的问题；安装事务现在使用归档记录的规范权限复核快照，同时继续严格校验文件路径、内容和四重身份。
- 继续保持官方 DSH Prompt、工具、Agent Loop、审批和会话为唯一执行权威；ChipMate 工具、索引、Memory、RAG 和上下文不会进入该 Agent。

## 1.1.1

相较 1.1.0：

- 高可信代码注释改为校验添加注释后的完整函数，由插件自动提取纯注释插入；自定义宏、属性及多行声明前缀不再因模型复制锚点差异而随机失败。
- 修复高可信代码注释失败后仍等待用户处理右下角通知、导致再次生成时误报“已有任务正在生成或等待确认”的问题。
- 复杂函数会根据控制区域生成分散的关键行间注释，优先解释分支目的、状态变化、错误回退、调用顺序和所有权；重复初始化类长函数不会机械增加注释。
- 修订既有函数说明时保留 Doxygen 标签集合、顺序、参数方向和名称、返回值标识及自定义标签，避免删除 `@brief`、`@param`、`@note`、`@return` 等原有结构。
- 关闭或放弃高可信注释 Diff 后会保留并原位恢复生成前的源码标签、编辑器组、光标选区和查看位置，不再连同未固定的源码预览标签一起关闭。
- 插件更新会先在后台下载并校验，点击一次“安装并重载窗口”后才覆盖安装并完整重载；不再依赖 VS Code 的“Restart Extensions”，更新日志会完整记录安装、重载和新宿主激活结果。
- 注释模型只返回函数和控制区域的短锚点及注释文本，由插件基于原始源码构建 Diff；不再因模型调整空行、缩进、宏或声明前缀而误报修改或遗漏源码。
- 函数说明会覆盖源码能够证明的契约、状态和副作用，复杂长函数会获得更详细且分散的关键逻辑注释；恢复会话只补齐尚未覆盖的安全区域。
- 仅覆盖数量不足、但已通过源码、Doxygen 标签和注释安全校验的候选会自动打开明确标识的降级 Diff；代码修改、锚点无效或注释夹带代码等错误仍会阻止应用。
- 新增 C/C++ 声明高可信注释，支持 `struct`、`union`、`enum`、`typedef`、文件或命名空间全局变量，以及函数外对象宏和函数宏。
- 新增统一源码注释入口：纯函数继续使用原有成熟函数流水线，声明使用独立锚点协议和校验器，混合选区会合并为一个只读 Diff 并一次原子应用。
- 修订既有声明说明时完整保护 Doxygen 标签和自定义标签；所有候选仍由插件基于源码快照构造，并校验锚点、宏边界和非注释 token 完全一致。

## 1.1.0

相较 1.0.19：

- 修复 1.1.0 启动服务器时遗漏 Skill Market 运行时服务、导致 CLI 在数据库迁移完成后立即退出的问题。
- 在索引服务启动前迁移 1.0.19 的全局与项目配置、认证、模型选择、VS Code 状态和会话中的旧 provider 标识，保留 Embedding API Key、端点、模型、维度、文档目录及其他索引设置；新旧配置冲突时以最近修改的一份为准，时间相同或无法判定时保留当前 ChipMate 数据，并合并非冲突字段及保留可恢复备份。
- API Key 单独变化时现在只重建连接并重新验证 Embedding 服务；向量空间指纹一致时继续使用原 active generation，并仅扫描新增或修改文件，不再强制清空 Document RAG 缓存和重复嵌入。
- 从 1.0.19 升级时现在会保留向量空间未变化的 Code RAG 文件缓存；内置忽略规则调整只协调新增、删除或改动的文件，不再重新嵌入未修改的代码。
- 修复内网包升级后主模型 provider 未进入 CLI 运行配置、导致旧会话发送消息时出现 `JSON Parse error` 的问题；迁移后的认证和会话现在可以继续使用同一聊天模型。
- 修复内网包升级后已存在的 ChipMate Provider 认证被 Gateway 状态覆盖并从设置页隐藏的问题；现在可直接编辑原 Provider，不再提示 Provider ID 已存在，也不会在清除 API Key 时删除模型和端点配置。
- 完成产品命名空间隔离：源码、包、命令、配置、环境变量、资源与构建流程统一使用 ChipMate 标识，不再携带或访问上游产品的运行时入口与配置路径。
- 同步上游 `v7.4.21` 的核心、SDK 与服务端改进，并保留 ChipMate 扩展、索引、Agent Manager 和内网离线能力的完整兼容。
- 文档索引现在会持续跟踪文件新增、修改与删除，并在后台索引或重建期间自动收敛最新变更，减少手动刷新与重复重建。
- 文档索引现在会在扫描 PDF 前验证实际选中的 Poppler 运行时；Windows 中文或空格路径抽取异常会立即停止候选代并保留上一版可用索引，避免逐份产生重复错误。
- 损坏、加密、不可用或超过安全限制的单个文档不再拖垮正常文档索引；更新失败的旧文档保留上一版向量，并提供分类汇总与完整中文诊断复制。
- Windows PDF 提取器现在随包携带经审计的 x64 VC++ 运行库，并修正内置预检 PDF 的内容长度，普通用户无需管理员权限安装系统运行库。
