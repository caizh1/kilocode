# ChipMate Server UI 验收规则

本文件适用于 `server/chipmate-word-render/`，并继承仓库根目录 `AGENTS.md` 的全部规则。

## 视觉实现范围

- 默认只实现和验收桌面端。除非用户明确提出移动端需求，不为移动端做视觉适配、截图签收或通过结论。
- 自动化检查中的窄宽度无溢出断言不等于移动端视觉验收。
- UI、卡片、按钮、图标和状态必须保持 iOS 26 Liquid Glass 的通透、分层、折射、高光、细腻边界、轻盈阴影和柔滑反馈。

## 真实 Chrome 截图认证

- 视觉认证必须使用本机 macOS 上用户真实安装的 Google Chrome 截图。Playwright 自带 Chromium、Playwright 截图、应用内浏览器截图和模拟浏览器截图都不能作为视觉通过证据。
- Playwright Chrome 项目可以用于功能、可访问性和性能自动化，但不能代替真实 Chrome 的视觉截图认证。
- 主对照尺寸为 `1484×1060`；补充桌面尺寸为 `1440×1024` 和 `1050×1024`。截图时必须固定浏览器缩放、页面主题、数据、轮播位置和交互状态。
- 原始截图、组件裁切图和对照证据统一放入 `.runtime/design-qa/`，并在 `design-qa.md` 记录浏览器、视口、主题、状态、差异和修复结果。

## 组件级材质对照

- 先列出页面上的容器和小组件，再逐个与设计图对照；不能只凭整页观感签收。
- 每个容器都要检查：主色与饱和度、透明度、背景模糊、折射、景深、玻璃厚度、高光、阴影、边界、圆角、图像裁切、对比度、间距、溢出以及 hover/focus/active/disabled 状态。
- 卡片、预览卡、排名徽标、图标容器、按钮、进度条、导航和搜索框都必须分别检查材质感；几何位置接近但材质明显不同不能判定通过。
- 对照必须把参考图和相同视口、相同状态的真实 Chrome 截图放在同一比较输入中，修复可见差异后重新截图复核。
- 存在 P0、P1 或 P2 视觉问题时不得交付；`design-qa.md` 只有在全部桌面检查完成后才能以 `final result: passed` 结束。
