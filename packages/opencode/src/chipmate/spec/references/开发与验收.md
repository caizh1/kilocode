# 开发与验收

## 实现与验证

在已确认的计划范围内完成任务，自主选择执行方式。保证实现依据仍有效；发现设计缺口、来源变化或超出范围的行为时核对并重新确认受影响部分，避免按失效结论编码。

保护当前文件与已有改动，遇到冲突先讨论。执行与改动相关的构建、静态检查和测试，记录真实环境、命令、结果及证据。测试预期来自设计、既有测试或硬件依据，不能仅靠新代码和配套测试相互证明。

必要的人工 FPGA 操作应说明目的、预期及需返回的结果。无法运行的检查标明未验证；工具失败或软件检查通过均不能替代实际板测结果。

## 审核与交付

从已确认条款反查实现与验证，开展对抗审核，检查实际相关的接口、并发、异常恢复、资源归属等风险，寻找遗漏和反例。遵循项目的 P0/P1 判定与反证规则，审核方式按任务需要选择。

交付材料列明实现范围、条款映射、验证结果、成立问题与未验证项，区分软件检查、硬件验证和生产效果。按主指引请求第三次确认，依据实际回答记录验收或继续修订。提交、合并和发布遵循项目原有授权。

使用实际样本记录阅读、答疑、纠错、审核及验证的人工耗时，与人工基线比较；没有真实模型或目标环境证据时，不宣称质量和效率目标已达到。
