# ChipMate 一键诊断

入口为“设置 → 关于 ChipMate → 社区与支持”。点击“提交诊断”，按需填写问题描述并选择最近 1 小时、24 小时或 7 天，确认后自动收集、打包、上传并核对服务端收据。成功后将诊断编号交给支持人员。

“保存日志包”不需要登录。命令面板也提供 `chipmate.v2.diagnostics.submit` 和 `chipmate.v2.diagnostics.export`；原生命令通过输入框、时间选择和原生进度通知操作，在 Webview 不可用时仍可收集。原生入口不附加会话正文。

## 内容与边界

默认收集扩展、CLI 主日志、模型请求元数据、索引状态及可读取的文档完整诊断、更新、技能和运行时事件。环境信息来自实际扩展宿主和当前 Profile。Remote-SSH 的扩展与 CLI 记录位于远端，Webview 事件明确标识来源。

默认排除聊天、工具正文、源码、文档原件、索引数据库、终端历史和完整用户配置。勾选会话附件后，采集当前会话及其直接关联子任务树的已有文本；最多 32 个会话、每个最近 200 条消息、合计 8 MiB。附件再次过滤凭据，仍可能包含业务内容。

记录和导出分别脱敏。日志包包含版本化清单、中文摘要、环境信息、分来源日志、只读状态快照及可选会话附件。清单记录文件大小、SHA-256、采集缺项与裁剪信息。日志只针对启用诊断底座后实际留下的记录；不能补回扩展无法激活、远端不可达或故障前未保存的证据。

本地记录保留 7 天、预算 100 MiB，完整包最多保留 3 个、7 天。用户另存的文件由用户管理。ZIP 最大 50 MiB，展开最大 100 MiB；达到归档预算时优先保留错误和近期记录。状态查询逐项限时，状态采集总预算 60 秒；任务取消会终止采集或传输。

## Server 配置

先升级 Server，再交付客户端。服务使用现有 LDAP 设备授权、用户身份及管理员名单；诊断上传不走 VSIX 发布接口。数据库在启动时执行第 12 号迁移，保留既有用户与资源归属。

|配置|默认值|
|---|---|
|`DIAGNOSTICS_ROOT`|数据库数据目录下的 `diagnostics`|
|`DIAGNOSTICS_QUOTA_BYTES`|10 GiB|
|`DIAGNOSTICS_MAX_ACTIVE`|4 个上传|
|`DIAGNOSTICS_MIN_FREE_BYTES`|沿用 `EXTENSION_UPLOAD_MIN_FREE_BYTES`，未配置时 2 GiB|

诊断目录必须是私有持久卷，不挂到静态站点。每次列表、详情和下载均验证身份：普通用户只能读取自己的记录，现有管理员可以读取全部。保留时间固定 7 天，到期立即拒绝访问，后台每分钟清理；启动时回收未完成上传和孤立文件。提交、下载、拒绝和清理写入现有认证审计，不记录日志正文。

管理员与用户均通过 Server 顶部“诊断日志”进入 `/diagnostics`，可按编号或提交人、版本、平台和时间筛选，查看摘要、完整度并下载。

|接口|用途|
|---|---|
|`GET /api/v1/capabilities`|返回诊断格式、大小及保留时间|
|`POST /api/v1/diagnostics/bundles`|流式接收并校验 ZIP|
|`GET /api/v1/diagnostics/bundles`|查询当前身份可见的记录|
|`GET /api/v1/diagnostics/bundles/:id`|查询提交结果与摘要|
|`GET /api/v1/diagnostics/bundles/:id/archive`|逐次鉴权下载|

上传使用 `application/vnd.chipmate.diagnostics+zip`，提供实际 `Content-Length`、`Idempotency-Key` 和 `X-Content-SHA256`。相同账号、编号和内容返回原记录；不同内容不能覆盖。服务端完成归档路径、展开预算、清单和哈希校验，原子保存并登记数据库后，客户端仍通过详情接口核对编号、大小和 SHA-256 才显示成功。

## 失败处理

旧 Server 不支持诊断、登录取消、凭据失效、离线、超时或空间不足时，显示具体原因并保留完整本地包供另存。账号或 Server 切换不会将旧任务的数据上传到新身份或新目标。

结果不确定时使用原编号查询；重试复用原包和编号。取消不会撤回服务端已经完成的提交。敏感诊断只向已配置的 Server 提交，认证请求拒绝跨源重定向。

## 上线验收

先在隔离环境验证新数据库迁移、能力声明、设备授权、上传、记录页、下载和到期拒绝，再在实际内网升级 Server。客户端按实际目标分别安装验收：macOS 本地、Windows 本地、Linux Remote-SSH。源码检查和开发构建不能代替这些目标机结果。

收集不少于 10 个真实故障样本，逐例记录人工采集点击数、耗时、补要日志次数，再用一键诊断复现同一流程。只有无需补要常规日志的样本比例达到 90%，且操作数与耗时分别下降 80%，才能签署效率验收；固定程序测试不直接证明这些指标。
