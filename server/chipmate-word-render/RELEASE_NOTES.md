# ChipMate Server 1.2.4

新增独立 Word 页面转图接口，供插件读取详设公式和图表。原 `/render/word` 继续用于 Word 生成与交付检查，契约保持不变。

- `POST /convert/word-to-images` 只将 DOCX 转为指定页 PNG，不调用目录刷新、页码回填或旧渲染处理器，不修改原始 Word。
- 支持真实页码、分批读取、空白页诊断、范围和图片校验，以及超时、取消、独立进程与临时目录清理。
- 镜像继续包含既有 LibreOffice、Poppler、字体和 Windows/Linux DeepSeek Harness 运行时，不增加转换服务。
- 先升级 Server，再安装 ChipMate 1.2.18 插件。已使用 1.2.3 的环境沿用原数据目录和认证密钥，无新增数据迁移。
- 已完成本机源码、真实转换、图页接入及旧接口回归。内网原文、Qwen 和目标机运行仍需现场验收。

## 平台发布基线及升级说明

本次受保护平台清单的上一 Server 发布为 1.2.2；1.2.3 已有本地交付包。自平台 1.2.2 升级还包含以下 1.2.3 的管理员授权变化与步骤；已安装 1.2.3 的用户无需重复首次授权。

### 1.2.3 管理员授权变更

相对 1.2.2，本版将管理员权限改为 Server 本地名单管理。

- 普通用户与未登录用户不再看到“认证设置”，直接访问也不能读取配置、身份映射或管理员名单。
- LDAP 负责身份验证与准入；旧 Admin Filter 仅保留配置，不再授予权限。
- 管理员按不可变 objectGUID 授权，支持查询、明确确认授权、撤权及最后管理员保护。同名与市场账号映射不会转移管理员角色。
- 角色和身份映射变更撤销相关 Web／设备凭据；退出网页同时结束本浏览器的应急管理会话。
- 补齐设备授权在并发撤权时的检查，防止撤权后继续写入令牌。

### 升级与首次授权

1. 停止旧服务后，对原市场数据目录及认证密钥文件制作一致性备份。保留原镜像和完整数据备份用于回滚。
2. 在离线包目录按原方式运行 `sudo bash install-render-server.sh`，沿用原数据目录和密钥，不删除历史数据。
3. 数据库升级到 v11 时清除旧认证会话，管理员名单初始为空；不根据姓名、LDAP 标记或旧会话自动授权。
4. 打开 `http(s)://你的服务器/admin/login`，使用原 break-glass 密钥登录。该应急入口不在公共导航中。
5. 在“管理员管理”输入 LDAP 用户名，查询后核对邮箱、目录身份标识及关联市场账号 ID，再确认授权。被授权者重新使用 LDAP 登录后可见“认证设置”。
6. 历史插件、收藏和发布归属不因本次管理员迁移而改写；本版不自动合并同名账号。

应急密钥只在服务器本机读取并输入自己的 Server 页面，不要发送给他人。回滚必须配套恢复升级前数据库和镜像，不要仅降低镜像版本。

### 1.2.3 验证边界

源码构建、类型检查、Lint、管理员及认证目标测试和 Chrome 功能／无障碍检查已通过。全套测试另有旧 Skill 归档安装用例失败。规定的三尺寸真实 Chrome 视觉验收、真实 AD 和目标服务器运行验收未完成；包发布成功不代表这些验收通过。
