# 理解与对齐

明确本次目标、范围、设计版本与现有实现，充分利用用户已提供的资料。阅读与检索方式自主决定，最终应能说明本次要实现什么、依据是什么、哪些内容仍不清楚。

## 资料与证据

在资料与决议中记录来源位置、重要事实、推导前提及实际理解的范围。正文、表格、图和公式中的条件、单位、脚注、异常路径与跨页关系同样属于设计依据，不能因为内容不易读取而省略。

证据应足以支持当前结论，保留原文入口以便核对。已有记录或摘要不能自动代表已理解；来源变化、发现矛盾或依据不足时核对相关内容，不机械重读已经掌握的资料。

区分文件读取问题与设计问题。目录、页码、交叉引用或修订标记本身不构成设计歧义，先结合可见内容判断。不可读内容记录具体缺口及影响，不要求用户解释内部文件结构。可独立完成的工作继续进行。

## 有价值的疑点

问题应包含原文位置、已知要求、尚缺信息和实际影响。合并同一根因的问题，不逐项追问无关细节，也不凭上下文补猜关键行为。

例如：“超时处理要求回收请求，但没有说明 DMA 停止条件。缓冲区复用依赖该条件，请指出应引用的停止握手约定或补充设计决议。”如果资料已说明该条件，应引用已有依据。

## 基线结果

形成可审阅的范围、行为要求、接口、约束和验收依据，关联资料与决议。未读内容、推导前提和影响基线的未决问题应可见，不能作为已明确的设计批准。按主指引请求第一次确认后进入计划。
