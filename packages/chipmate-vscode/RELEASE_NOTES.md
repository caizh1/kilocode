# ChipMate 1.1.0

相较 1.0.19：

- 修复 1.1.0 启动服务器时遗漏 Skill Market 运行时服务、导致 CLI 在数据库迁移完成后立即退出的问题。
- 在索引服务启动前迁移 1.0.19 的全局与项目配置、认证、模型选择、VS Code 状态和会话中的旧 provider 标识，保留 Embedding API Key、端点、模型、维度、文档目录及其他索引设置；新旧配置冲突时以最近修改的一份为准，时间相同或无法判定时保留当前 ChipMate 数据，并合并非冲突字段及保留可恢复备份。
- API Key 单独变化时现在只重建连接并重新验证 Embedding 服务；向量空间指纹一致时继续使用原 active generation，并仅扫描新增或修改文件，不再强制清空 Document RAG 缓存和重复嵌入。
- 从 1.0.19 升级时现在会保留向量空间未变化的 Code RAG 文件缓存；内置忽略规则调整只协调新增、删除或改动的文件，不再重新嵌入未修改的代码。
- 修复内网包升级后主模型 provider 未进入 CLI 运行配置、导致旧会话发送消息时出现 `JSON Parse error` 的问题；迁移后的认证和会话现在可以继续使用同一聊天模型。
- 修复内网包升级后已存在的 ChipMate Provider 认证被 Gateway 状态覆盖并从设置页隐藏的问题；现在可直接编辑原 Provider，不再提示 Provider ID 已存在，也不会在清除 API Key 时删除模型和端点配置。
- 完成产品命名空间隔离：源码、包、命令、配置、环境变量、资源与构建流程统一使用 ChipMate 标识，不再携带或访问上游产品的运行时入口与配置路径。
- 同步上游 `v7.4.21` 的核心、SDK 与服务端改进，并保留 ChipMate 扩展、索引、Agent Manager 和内网离线能力的完整兼容。
- 文档索引现在会持续跟踪文件新增、修改与删除，并在后台索引或重建期间自动收敛最新变更，减少手动刷新与重复重建。
- 文档索引现在会在扫描 PDF 前验证实际选中的 Poppler 运行时；Windows 中文或空格路径抽取异常会立即停止候选代并保留上一版可用索引，避免逐份产生重复错误。
- 损坏、加密、不可用或超过安全限制的单个文档不再拖垮正常文档索引；更新失败的旧文档保留上一版向量，并提供分类汇总与完整中文诊断复制。
- Windows PDF 提取器现在随包携带经审计的 x64 VC++ 运行库，并修正内置预检 PDF 的内容长度，普通用户无需管理员权限安装系统运行库。
- 升级时会按最后修改时间合并新旧索引配置，保留用户在降级版本中选择的 embedding 模型，避免模型被默认值替换并触发不必要的全量重建。
- 简化高可信代码注释审阅流程：单函数生成后直接打开 Diff；源码预览标签被替换或关闭时会自动重新打开目标文件，点击一次即可安全应用，不再误报“目标文档已关闭”。
- 修复高可信代码注释失败后仍等待用户处理右下角通知、导致再次生成时误报“已有任务正在生成或等待确认”的问题。
- 关闭或放弃高可信注释 Diff 后会保留并原位恢复生成前的源码标签、编辑器组、光标选区和查看位置，不再连同未固定的源码预览标签一起关闭。
- 插件更新会先在后台下载并校验，点击一次“安装并重载窗口”后才覆盖安装并完整重载；不再依赖 VS Code 的“Restart Extensions”，更新日志会完整记录安装、重载和新宿主激活结果。
- 复杂函数会根据控制区域生成分散的关键行间注释，优先解释分支目的、状态变化、错误回退、调用顺序和所有权；重复初始化类长函数不会机械增加注释。
- 修订既有函数说明时保留 Doxygen 标签集合、顺序、参数方向和名称、返回值标识及自定义标签，避免删除 `@brief`、`@param`、`@note`、`@return` 等原有结构。
- 注释模型只返回函数和控制区域的短锚点及注释文本，由插件基于原始源码构建 Diff；不再因模型调整空行、缩进、宏或声明前缀而误报修改或遗漏源码。
- 函数说明会覆盖源码能够证明的契约、状态和副作用，复杂长函数会获得更详细且分散的关键逻辑注释；恢复会话只补齐尚未覆盖的安全区域。
- 仅覆盖数量不足、但已通过源码、Doxygen 标签和注释安全校验的候选会自动打开明确标识的降级 Diff；代码修改、锚点无效或注释夹带代码等错误仍会阻止应用。
