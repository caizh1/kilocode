# 11 Feature Diff Completeness Rules

功能点是有触发、处理逻辑、输出/状态变化/副作用和证据的最小完整能力单元。不能把函数数量、代码行、文档章节、单个 if 分支等同功能点。

功能点分类：Both、CodeOnly、DocOnly。旧符号找不到时必须做演进映射，不得直接判定删除。

差异报告必须包含：报告摘要、模块定位差异、旧符号映射、功能点统计、Both 明细、CodeOnly 明细、DocOnly 明细、旧文档过期内容、当前源码新增能力、新详设改进点、风险与待确认事项。

## 1. 旧符号演进映射

旧函数、结构体、状态、宏、文件或章节线索未在当前源码直接命中时，继续检查重命名、拆分、合并、移动、内联、抽象层变化、条件编译和平台分支。只有证据排除了合理演进关系后，才可标记为已删除或 `DocOnly`。

```md
| 旧符号/能力 | 当前候选 | 演进类型 | 支撑证据 | 结论 | 置信度 | owner-review 项 |
|---|---|---|---|---|---|---|
```

## 2. 功能差异明细

```md
| 功能ID | 功能说明 | 分类 | 当前所属设计单元 | 触发 | 处理结果/副作用 | 旧文档位置 | 当前源码证据 | 风险/处理建议 |
|---|---|---|---|---|---|---|---|---|
```

- `Both`：旧文档和当前源码都存在，但仍需说明行为、边界或实现是否变化；
- `CodeOnly`：当前源码确认的新能力，必须进入新详设对应设计单元；
- `DocOnly`：旧文档存在但当前源码未确认，只进入差异、风险或待确认项，不进入当前设计正文确定结论。

## 3. 与更新流程的关系

更新现有 Word 时，先基于当前源码生成目标章节内容，再通过 ChipMate 通用 Word edit/style/diff 工具定点更新。不得因为旧文档存在就复述旧正文，也不得把差异报告变成新的事实来源。

只请求旧新差异时允许单独交付差异报告；不要自动扩展为完整 Word。完整 Word 场景中，差异与演进章节位于功能、函数、图和证据覆盖之后，假设与风险之前。
